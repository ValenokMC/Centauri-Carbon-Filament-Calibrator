# Calibration plates: where they come from

The short version: run `Prepare-Templates.cmd` once, follow it, and you are
done. This page explains why that step exists at all, because "download a tool
and then do ten minutes of setup" deserves an explanation.

## Why they are not in the download

Five of the six plates per material are **OrcaSlicer's own calibration models**:

| Plate | Where it comes from |
|---|---|
| `1_temperature.3mf` | Orca wizard → Calibration → Temperature tower |
| `2_flow.3mf` | Orca wizard → Calibration → Flow rate |
| `2b_shrinkage.3mf` | **Geometry generated by this project**; the full project is built locally |
| `3_pressure_advance.3mf` | Orca wizard → Calibration → Pressure Advance |
| `4_max_flow.3mf` | Orca wizard → Calibration → Max volumetric speed |
| `5_retraction.3mf` | Orca wizard → Calibration → Retraction test |

Those five are good models. The blocks carry printed labels, and they include
real test features — bridges, overhangs, stringing transitions — that a plain
box does not have. Substituting bare geometry would make the tests worse.

But the terms under which those models may be redistributed **separately from
OrcaSlicer** are not stated anywhere this project can point to. Publishing them
in a GitHub repository on a guess is not something a public project should do.

So: this repository ships the recipe and the tooling. You already have
OrcaSlicer, and OrcaSlicer already gives you those models. The plates get built
on your machine, from your copy.

## What `Prepare-Templates.cmd` does

**Step 1 — one saved Orca project becomes the local settings donor.**

A useful `.3mf` needs more than geometry. Orca stores several hundred machine,
process and filament settings in the project, including the real start G-code.
Inventing a minimal configuration here would be unsafe, and shipping one
person's configuration would be both unsafe and wrong for everybody else.

The first wizard plate you import is therefore copied into your data folder and
sanitised. Its printer address and personal preset names are removed. That
local-only copy donates settings to the project's own geometry; it is never
added to the repository or a release archive.

**Step 2 — the shrinkage plate, generated.**

A 100 × 10 × 3 mm bar, built vertex by vertex by `geometry.py`, for each of the
eight materials. No model is downloaded or copied from the donor. The geometry
is verified after generation: the bar has to come out exactly 100 mm, or the
build fails. The donor contributes only the local Orca settings needed to slice
it safely on this machine.

The 100 mm baseline is deliberate. Over 30 mm the shrinkage disappears into a
caliper's tolerance.

**Step 3 — the five from Orca's wizard.**

For each one:

1. In OrcaSlicer, open **Calibration** and run the test.
2. When the wizard has built the plate, **File → Save Project As**, anywhere.
3. Back in `Prepare-Templates.cmd`, choose the material and the plate, and give
   it the path to the file you just saved.

It is copied into your data folder, and **sanitised on the way in**:

- `print_host` and every related key is removed
- the printer preset id is replaced with the neutral system name
- the filament preset id is replaced with a `@System` profile compatible with
  any printer

That last one matters more than it looks. Elegoo's own filament profiles list
their compatible printers by name and know nothing of your presets; a plate
bound to one would be left without a filament, and Orca would silently
substitute an arbitrary one with arbitrary temperatures.

## Doing it once, for one material

You do not have to build all eight materials. Build the ones you actually print.
`Doctor.cmd` shows what you have:

```
Шаблоны плит
  готовых проектов: 9 из 48
     PLA       2 из 6
     PETG      1 из 6
     ...
```

A material with a missing plate still works — the calibrator tells you which
test to run manually from Orca's menu, and still does the arithmetic.

## Where they end up

```
%LOCALAPPDATA%\CentauriCarbonFilamentCalibrator\templates\
├── PLA\
│   ├── 1_temperature.3mf
│   ├── 2_flow.3mf
│   └── ...
└── PETG\
    └── ...
```

A plate found here wins over the one shipped in the program folder, so your
build always takes priority and an update cannot overwrite it.

## What happens to them during a calibration

A template is **opened read-only, always**. It is shared by every spool of that
material, and a template picking up one spool's values would silently poison the
next calibration.

For each plate, the calibrator writes a **personal copy** into that run's folder:

- your machine preset
- your measured values so far — so the temperature plate prints at the base
  temperature, but the flow plate prints at *your* temperature, the PA plate at
  *your* flow, and so on
- your `print_host`, if you have one configured

That copy is the file that opens in OrcaSlicer. The template is not touched.

## The reference cube

`templates/reference-cube.3mf` is a plain 25.6 mm cube generated by this project.

It exists because building a full Orca project needs a machine configuration —
several hundred keys including the real start G-code — and the original workflow
kept a saved project around as the donor for it. Only the configuration was ever
read; the geometry was never reused.

That configuration is now read from the **first project you save from your own
OrcaSlicer wizard**. The copy is sanitised and stays in your local data folder,
so nothing machine-specific ships. The cube is kept as a neutral, verifiable
geometry reference: it is the smallest thing that proves the project-writing
code works, and it can be regenerated from eight vertices by anybody who wants
to check.

## If OrcaSlicer clarifies the licence

If the OrcaSlicer project states terms allowing these models to be
redistributed, this whole step disappears and the plates ship ready-made. That
would be a real improvement, and there is
[an open invitation](../THIRD_PARTY_NOTICES.md) to say so.
